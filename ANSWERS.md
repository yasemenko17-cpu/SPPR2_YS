# Відповіді на практичну роботу №2 (Варіант 23)

1. **Зіставлення викликів Python із системними викликами Linux**

Під час виконання функції аналізу дерева каталогів Python взаємодіє з ядром операційної системи. Нижче наведено приклади зіставлення викликів у Python та реальних системних викликів Linux, зафіксованих за допомогою `strace`:

* **Отримання метаданих файлу/посилання:**
  * Виклик у Python: `os.lstat(full_path)`[cite: 15]
  * Системний виклик Linux: `newfstatat(AT_FDCWD, "шлях", ..., AT_SYMLINK_NOFOLLOW)` — дозволяє ядру отримати атрибути (розмір, тип, inode) файлу чи символічного посилання за заданим шляхом безпосередньо через дескриптор, не розгортаючи при цьому самі символічні посилання[cite: 15].

* **Відкриття та сканування каталогів:**
  * Виклик у Python: `os.walk(root)` та `os.listdir(current_root)`[cite: 15]
  * Системний виклик Linux: `openat(AT_FDCWD, "шлях_до_каталогу", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY)` — відкриває каталог як спеціальний файл для подальшого зчитування його елементів ядром.

2. **Граничні випадки, які були перевірені у тестах (`tests/test_my.py`)**

У власних тестах було перевірено такі граничні сценарії:
1. **Порожній каталог:** перевіряє коректність обробки структури, де немає жодних файлів. Лічильники файлів, каталогів та посилань дорівнюють нулю, а для найбільшого файла повертається рядок `"Найбільший: немає"`.
2. **Каталог лише з символічним посиланням:** перевіряє, що символічні посилання враховуються окремо і не зараховуються помилково до звичайних файлів чи каталогів.
3. **Кілька звичайних файлів різного розміру:** перевіряє правильність визначення найбільшого за розміром файла (`largest_path`) і коректність підрахунку сумарного розміру байтів.

3. **Помилки ядра та їх обробка у коді**

Під час сканування файлової системи код може стикатися з різноманітними системними помилками ядра Linux, такими як `PermissionError` (відсутність прав доступу на читання певного підкаталогу) або `FileNotFoundError` (якщо файл було видалено під час роботи програми).

Для запобігання аварійному завершенню (крашу) такі операції обгорнуті в блоки безпеки `try...except OSError:`:
* Помилки доступу до окремих підкаталогів усередині `os.listdir()` перехоплюються, і каталог просто повертає порожній список (`entries = []`).
* Недоступні або биті елементи під час виклику `os.lstat()` безпечно пропускаються за допомогою `continue`, що дозволяє успішно завершити обхід решти доступного дерева каталогів.
